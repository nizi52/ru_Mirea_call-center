# Подготовка к защите КР №2 (JavaFX)

## Что делает программа

Настольное приложение работает с базой PostgreSQL из КР №1. Основная сущность — обращение (`Appeal`), связанная с клиентом, оператором и отделом. В главном окне есть таблица обращений, поиск, фильтры, сортировка, добавление, редактирование, просмотр связанных данных, смена статуса, удаление, статистика и экспорт.

## Архитектура

`FXML + CSS (View) → Controller → Service → Repository (JDBC) → PostgreSQL`

- **View.** FXML-файлы в `resources/ru/mirea/callcenter/ui` описывают окна, `style.css` — оформление.
- **Controller.** Принимает действия пользователя, собирает данные формы и показывает результат. Бизнес-правил и SQL не содержит.
- **Service.** Правила предметной области, фильтрация и сортировка (`AppealService.find`), статистика (`AppealStatistics`), выбор формата экспорта (`ExportService`).
- **Repository.** Только SQL через `PreparedStatement`.
- **Database.** Таблицы, связи и ограничения (`PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `NOT NULL`, `CHECK`) из `database/init.sql`.

## Вопросы из задания и ответы

**Как запускается JavaFX-приложение?** `mvn javafx:run`: `javafx-maven-plugin` запускает `ru.mirea.callcenter.ui.App`, который наследует `javafx.application.Application`. Перед этим должна работать БД (`docker compose up -d --wait`).

**Stage, Scene, Node.** `Stage` — окно, `Scene` — содержимое окна, `Node` — любой элемент дерева интерфейса (кнопка, таблица, контейнер). В `App.start` загружается FXML, его корневой узел (`BorderPane`) становится корнем `Scene`, а `Scene` помещается в `Stage`.

**Зачем FXML.** Разметка отделена от логики: интерфейс описывается декларативно, код контроллера остаётся коротким, внешний вид можно менять без перекомпиляции логики.

**Как FXML связан с Controller.** Атрибут `fx:controller` в корневом элементе указывает класс. Элементы с `fx:id` загрузчик подставляет в поля контроллера с аннотацией `@FXML`. Атрибут `onAction="#метод"` вызывает метод контроллера. После загрузки вызывается метод `initialize()`.

**Как обновляется TableView и зачем ObservableList.** Таблица привязана к `ObservableList<Appeal>`. Когда список меняется (`appeals.setAll(...)`), он сам уведомляет таблицу, и она перерисовывается без ручного `refresh()`. Обычный `List` такого уведомления не даёт.

**Где бизнес-логика.** В пакете `service`: переходы статусов (`nextStatuses`), проверка оператора и лимита нагрузки, валидация полей.

**Где работа с данными.** В пакете `repository`: SQL и `ResultSet` → объекты модели. Соединение даёт `DatabaseManager`.

**Как обрабатываются исключения.** `BusinessException` и `EntityNotFoundException` содержат готовое сообщение для пользователя. `SQLException` переводится в понятный текст (`DbErrors`: например, SQLState `23505` — нарушение уникальности). Все ошибки показывает `AlertUtil.run` через диалог; технические подробности пишутся в лог (`slf4j`), а не показываются пользователю. Пустых `catch` нет.

**Как проверяются данные.** В `AppealService` до записи: обязательные поля, длина темы, допустимая категория, существование клиента и оператора, активность оператора, лимит пять активных обращений. Исключение несёт код поля, и форма подсвечивает его красной рамкой. Дополнительно ограничения продублированы в БД (`CHECK`, `NOT NULL`, `FOREIGN KEY`).

**Как реализованы поиск и фильтрация.** `AppealService.find(AppealFilter)` берёт все обращения одним запросом и через Stream API применяет условия: текст (клиент, телефон, тема), статус, категория, период дат. Любое изменение поля поиска или фильтра заново вызывает `reload()`. Сортировка выбирается в списке (`Comparator`), а клик по заголовку столбца использует встроенную сортировку `TableView`.

**Как считается статистика.** `AppealStatistics.of(список)` — чистая функция от списка обращений: группировки `Collectors.groupingBy` по статусу, категории и оператору, среднее время закрытия через `Duration`, доля эскалированных. Считается по обращениям, показанным в таблице. Для периода достаточно выставить даты в фильтре.

**Как выполняется экспорт.** `FileChooser` возвращает путь, `ExportService` по расширению выбирает `ExcelExporter` (Apache POI, `.xlsx`) или `CsvExporter` (`.csv` с BOM, чтобы Excel правильно показал кириллицу). Выгружается то, что сейчас в таблице.

**Как запускается готовая система из архива через Docker и как проверяется состояние.** Из корня распакованного архива: `docker compose --env-file .env -f backend/docker-compose.yml up -d --wait`. Проверка: `http://localhost:8080/` и `http://localhost:8080/actuator/health`, `docker ps` показывает контейнеры PostgreSQL (healthy) и backend. Остановка: `docker compose --env-file .env -f backend/docker-compose.yml down` без удаления volume. Свой JavaFX-клиент в Docker не запускается, он подключается по JDBC к PostgreSQL из КР №1 (`docker compose up -d --wait` в этом проекте).

## ООП и коллекции (из КР1)

- **Инкапсуляция:** поля моделей `private`, доступ через `get`/`set`.
- **Интерфейс и полиморфизм:** `Repository<T, ID>` реализуют `OperatorRepository`, `ClientRepository`, `DepartmentRepository`, `AppealRepository`.
- **Enum:** `AppealStatus` — фиксированный набор статусов.
- **Record:** `AppealFilter`, `AppealStatistics`, `AppealDetails` — неизменяемые объекты данных.
- **Коллекции:** `List`, `Set`, `Map`, `Stream API`.

## JDBC

`DatabaseManager` создаёт `Connection` из `database.properties` (или переменных окружения). Репозитории используют `PreparedStatement` с параметрами `?`: значения передаются отдельно от текста запроса, что защищает от SQL-инъекций. `try-with-resources` закрывает соединение, запрос и `ResultSet` даже при исключении.

## Что показать преподавателю

1. `docker compose up -d --wait`, затем `mvn javafx:run`: окно открывается, таблица заполнена.
2. Добавление обращения: сначала пустая форма (ошибка с подсветкой поля), затем корректные данные, запись появляется в таблице.
3. Редактирование (форма открывается с текущими значениями), просмотр (двойной клик по строке) со связанными клиентом и оператором.
4. Смена статуса: доступны только допустимые переходы; удаление с подтверждением.
5. Поиск, два и более фильтров, сортировка (список и клик по заголовку).
6. Статистика (семь показателей), экспорт в `.xlsx` и `.csv` через выбор файла.
7. Попытка назначить шестое активное обращение оператору и тема длиннее 300 символов.

## Честные ограничения

- Лимит «пять активных обращений» проверяется сервисом; при одновременной работе нескольких экземпляров приложения без блокировки в БД возможна гонка назначений.
- Данные загружаются в потоке JavaFX синхронно. Для объёма данных КР этого достаточно, но для большой базы нужно переносить запросы в фоновые задачи (`javafx.concurrent.Task`).
- Поиск и фильтры работают в памяти поверх полной выборки, а не динамическим SQL.
